# 交互与语言只读审查

未修改源码、用户配置或音频读取逻辑。以下问题使用当前项目方法复现；窗口、控件和慢速任务为测试替身，并非真实硬件操作。

复现：`python3 -B .validation/audit-interactions.py > .validation/audit-interactions.log`

证据脚本：`.validation/audit-interactions.py`；完整输出：`.validation/audit-interactions.log`。本次运行退出码 0，三项断言均复现。

## P1：关闭窗口可以截断尚未完成的配置事务

- 位置：`niri/shell/panel.py:222–228`、`323–344`、`1838`。所有后台操作均由 `daemon=True` 线程运行，窗口销毁会调用 `Application.quit()`，主程序随后退出。
- 触发：点击设置的“应用”，操作仍在进行时按关闭按钮、Esc 返回总览后关闭，或重复触发面板快捷键。语言切换重建窗口也应纳入生命周期检查。
- 证据：调用实际 `Panel.work()`，让任务向 `/tmp` 文件写第一阶段，延迟 2 秒后写第二阶段，并在 `finally` 写清理标记；调用实际 `on_destroy()` 后模拟 GTK 主循环退出。进程正常退出，但文件只有 `write_one`，`write_two` 和 `finally` 均未执行。
- 影响：已存在多步骤写入路径，例如 `desktop_settings.py:439–448` 在更新 KDL、通知 Niri、写状态文件之间有窗口；`appearance.py:405–418` 写多个主题文件；`system_settings.py:159–188` 的失败回滚依赖任务继续执行。这里确认的是退出机制会截断任务，未声称用户现有配置已经损坏。
- 修改指令：将有副作用的任务生命周期提升到应用级管理。关闭窗口只隐藏或解除界面订阅；让未完成写事务完整提交或回滚后再结束进程。可以使用应用级任务计数配合 hold/release 并推迟 quit，或独立持久 worker。区分可取消的只读任务和不可中途终止的提交任务；不要仅让销毁后的 UI 回调消失而忽略后端存活。
- 验收：用两个临时文件和可控延迟模拟提交及失败回滚，在 ×、Esc、重复面板快捷键、语言重建等路径触发关闭。每种情况下只能得到完整新状态或完整旧状态，不得只有部分文件更新；后端任务不得访问已销毁控件。无需真实锁屏、睡眠或修改硬件。

## P2：输入与窗口设置的重新读取会覆盖读取期间的新编辑

- 位置：`niri/shell/desktop_controls.py:110–125`。`refresh()` 只禁用刷新按钮；表单与应用按钮仍可操作，完成回调直接调用 `populate()`。
- 触发：进入“键盘与鼠标”或“窗口与工作区”，点击“重新读取”，在异步读取完成前修改数值。
- 证据：实际调用 `SettingsPage.refresh()` 并延迟回调，表单和应用按钮的敏感状态均仍为 True；读取期间输入 20，旧状态读取完成后变回 16。该复现使用控件替身，不依赖主机读取速度。
- 修改指令：读取期间冻结表单、应用和恢复默认按钮，保存并正确恢复原先的可操作状态；或者引入草稿版本号，迟到的读取结果不能覆盖读取开始后的编辑。不要把自定义 XKB 或原配置约束所禁用的控件一概重新启用。相同策略可用于 `display_controls.py:101–138` 的异步刷新，但后者不是本项复现目标。
- 验收：用延迟后端测试上述两个页面，读取期间不得接收随后被静默覆盖的编辑；读取成功和失败后控件状态正确，错误提示保留，原有自定义 XKB/焦点跟随约束继续生效。

## P2：快捷键总览仍有双语残留，英文描述还会丢失参数

- 位置：`niri/shell/shortcuts.py:112`、`116–127`；`niri/shell/panel.py:1467–1486`；`niri/shell/i18n.py:101–114`。
- 触发：分别选择中文、英文界面，打开快捷键总览，查看方向键、工作区或截图快捷键。
- 证据：当前 117 条快捷键中，英文模式 18 条描述仍含中文；中文模式 46 条匹配残留的英文/中文并列模式。例：两个语言下 Super+Left 都显示 `Focus / 聚焦 · Column / 列 · Left / 左`。英文 Super+1 和 Super+PageUp 都变为 `Go to workspace`，目的工作区/方向丢失；Print 仍显示 `Screenshot screen · 屏幕截图 · Clipboard only / 仅剪贴板`。
- 原因：生成器先拼接多个双语片段，通用 `tr_legacy()` 只处理单个分隔符；工作区参数拼在中文半句中，选择英文半句时一并丢失。
- 修改指令：在 `shortcuts.describe()` 中用结构化字段或 `tr()` 完整模板生成选定语言的动作、对象、方向、目标、跟随行为及截图保存模式；不要再拼接多个双语字符串交给 legacy 猜测。保留搜索支持两种语言的能力，显示与搜索索引应分开；不要通过扩大通用翻译规则误改设备名、路径或用户数据。
- 验收：当前所有 117 条快捷键在英文下无中文动作描述，中文下无重复英文动作名；工作区数字、上下方向、是否跟随窗口、截图保存/仅剪贴板信息均保留。切换语言后重新打开总览、双语关键词搜索和未匹配提示正常。
